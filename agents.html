AI agent automation

Agents that take routine work off nonprofit staff. They read, draft and check, then wait for a person to approve before anything is sent, published or assigned.

    How every agent is built

    All our agents share the same five-part structure, so partners know exactly where a person stays in control.

    Trigger

    A person or a schedule starts the run. Text inside a document or email never starts one.

    Plan

    The model breaks the task into steps, using only the tools this agent was given.

    Act with limited tools

    Each tool is allowed, needs approval, or never available. Numbers are computed in code, not by the model.

    Approval

    Anything sent, published or assigned waits for a person, who can approve it or send it back.

    Audit log

    Every step, tool call and approval is written to a log the partner can read.

    Guardrails

    Only the tools it needs

    Each agent gets the smallest set of tools its task requires, and no client records unless a partner approves in writing.

    Client data stays put

    Agents that touch client data run on the partner's own computer or systems. Nothing goes to outside AI services without written approval.

    Documents are data

    Text inside files, emails and web pages is treated as content to work on, never as instructions the agent follows.

    Stop and ask

    When the agent is unsure, it stops and asks a person instead of guessing.

    Tested on real tasks

    Each agent is measured on an open task suite: success rate, staff edits per output, send-back rate, and cost and time per run.

    Easy to switch off

    Partners can pause any agent at any time, and staff can always do the task by hand.
